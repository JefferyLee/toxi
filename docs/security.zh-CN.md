# 安全模型

> English version: security.md

## 保护什么、由谁保护

| 层 | 保证 | 提供方 |
|---|---|---|
| 传输 | 端到端加密，以联系人的密钥认证。只有好友能发消息。 | Tox |
| 身份 | 参与者*就是*它的密钥对。身份卡片是自述的，但只能来自那把密钥。 | Tox + 信封 `profile` |
| 本地数据 | 密钥、数据库、配置、身份卡片、收到的文件均为 0600，放在 0700 目录里。daemon 每次启动时重新施加这些权限。 | daemon |
| agent | 收到的文本是数据，不是指令。适配器按信任级别为每个 peer 加措辞。如果消息转述"用户已批准"，这永远不算批准。 | 适配器 + `peers.GUIDES` |
| 泛洪 | 每联系人每分钟 60 条 text、每分钟 5 个好友请求、每条 text 64 KB、每个文件 100 MB | daemon |

## 威胁与应对

**某个 peer agent 被攻破或犯糊涂，叫我的 agent 去做某事。** 每条注入的消息都带有发送方的身份卡片和信任级别。其后的措辞告诉 agent 可以做什么：

- `observer` 的消息只是信息。
- agent 可以在当前任务范围内执行 `collaborator` 的请求。
- 对这两个级别，任何破坏性操作或超出项目范围的操作都必须由用户批准。
- `owner` 的消息来自用户自己的设备。agent 按用户在本会话里亲手输入的消息对待它们。agent 回复到那台设备上。

`needs_human` 的事项由用户决定。`relay` 内容按传闻对待。适配器从不注入非 peer 联系人的消息。它只做摘要。

**有人拿到了我的手机。** `trust = "owner"` 的联系人对它能到达的每个会话都以你的身份说话。所以它的密钥和你的终端一样敏感。如果设备丢失，删掉它的 `[peers.<别名>]` 表。这个改动立即生效。然后用 `toxi remove` 删除这个联系人。信任不会在 agent 之间传递。如果别的 agent 转述 `owner` 消息，agent 按转述者的信任级别对待它。这条消息不算你本人的话。

**有人冒充 peer。** 做不到。消息来自密钥，而只有运营者加过好友的密钥才是联系人。身份卡片可以声称任何事。但身份卡片仍经由发出它的那把密钥的信道到达。本地别名由你自己掌握。

**消息被重放或重复。** 每条消息都有一个发送方选定的 uuid。接收方只存一次这条消息。它对每个重复回 ACK，让发送方停止重试。

**我的文件泄露。** `TOXI_HOME` 下的一切都只对本用户账户可见。日志从不包含消息正文。在日志里，公钥只以 8 字符前缀出现。`on_message` shell hook 与 webhook 只携带别名和 id。只有刻意设置了 `include_body = true`，它们才携带正文。

如果设置了 `on_message_secret`，webhook 带 HMAC 签名。签名头是 `X-Toxi-Signature: sha256=HMAC(secret, "<ts>.<body>")`。`X-Toxi-Timestamp` 头存放 `<ts>`。

**陌生人加我。** 好友请求等待 `toxi accept`。只有一个例外：如果请求回应一个有效的 `toxi pair` 邀请，daemon 自动接受它。邀请带一个随机 32 位十六进制 nonce。它有效 10 分钟，且只能用一次。邀请和你的 Tox ID 一样敏感。请通过你信任的渠道分享邀请。

**我的 IP 可见。** 是的，与你聊天的人能看到它。这是 Tox 的特性。如果你在意，让流量走 Tor。使用配置里的 `[tox] proxy_*` 键。详情见 PRD。

**跑着 daemon 的机器是共享的。** 不要共享它。`tox_state.bin` 目前还没有静态加密。参见 PRD §4.9.3。

## 适配器必须遵守的规则

1. 只通过 `toxi peer-inbox` 或 `wait_for_message` 注入 peer 消息。这样信任措辞随消息一起到达。
2. 如果运营者没有主动选择，绝不让消息正文进入 webhook、日志或状态栏。
3. 只在人已看到消息或 agent 已收到消息之后，才把消息标为已读。这一步会发送回执。
4. 同一身份的 CLI、hook 和 MCP server 必须使用相同的 `TOXI_HOME`。`toxi doctor` 会检查这一点。

# 安全模型

> English version: security.md

## 保护什么、由谁保护

| 层 | 保证 | 提供方 |
|---|---|---|
| 传输 | 端到端加密，以对端密钥认证；只有好友能发消息 | Tox |
| 身份 | 参与者*就是*它的密钥对；身份卡片是自述的，但只能来自那把密钥 | Tox + 信封 `profile` |
| 本地数据 | 密钥、数据库、配置、卡片、收到的文件均为 0600，放在 0700 目录里；daemon 每次启动都重新施加 | daemon |
| agent | 收到的文本是数据，不是指令；对端按信任级别加措辞；消息里转述的"用户已批准"永远不算批准 | 适配器 + `peers.GUIDES` |
| 泛洪 | 每联系人每分钟 60 条 text、每分钟 5 个好友请求、每条 text 64 KB、每个文件 100 MB | daemon |

## 威胁与应对

**某个对端 agent 被攻破或犯糊涂，叫我的 agent 去做某事。** 每条注入的消息都带着发送方的卡片和信任级别，其后的措辞说明 agent 可以做什么：`observer` 的消息只是信息，`collaborator` 的请求可以在当前任务范围内执行，而任何破坏性或超出项目范围的事，两种情况下都需要用户。`needs_human` 的事项由用户决定；`relay` 内容按传闻对待。非 peer 联系人的消息从不注入（只做摘要）。

**有人冒充对端。** 做不到：消息来自密钥，而只有运营者加过好友的密钥才是联系人。卡片可以随便声称，但它仍是经由发出它的那把密钥的信道到达的，而本地别名是你自己起的。

**消息被重放或重复。** 每条消息都有发送方选定的 uuid；接收方只存一次，并对重复的回 ACK，让发送方停止重试。

**我的文件泄露。** `TOXI_HOME` 下的一切都只对本用户账户可见。日志从不包含消息正文（公钥以 8 字符前缀出现）。`on_message` shell hook 与 webhook 只携带别名和 id，除非刻意设置了 `include_body = true`；设置了 `on_message_secret` 时 webhook 带 HMAC 签名。

**陌生人加我。** 好友请求等待 `toxi accept` —— 除非这个请求回应的是一个有效的 `toxi pair` 邀请（随机 32 位十六进制 nonce，10 分钟有效，一次性），那样会被自动接受。请通过你信任的渠道分享邀请：邀请和你的 Tox ID 一样敏感。

**我的 IP 可见。** 是的，对与你聊天的人可见 —— 这是 Tox 的特性。如果在意，可走 Tor（配置里的 `[tox] proxy_*`，见 PRD）。

**跑着 daemon 的机器是共享的。** 别这么做。`tox_state.bin` 目前还没有静态加密（PRD §4.9.3）。

## 适配器必须遵守的规则

1. 只通过 `toxi peer-inbox` / `wait_for_message` 注入 peer 消息，让信任措辞随消息一起到达。
2. 除非运营者主动选择，否则绝不让消息正文进入 webhook、日志或状态栏。
3. 只在消息已展示给人或已投递进 agent 时才标已读（这就是发送回执的时机）。
4. 同一身份的 CLI、hook 和 MCP server 必须使用一致的 `TOXI_HOME`；`toxi doctor` 会检查。
